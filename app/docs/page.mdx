# Overview

CrawlerToll is **open-source Node middleware for the AI-crawler economy**. It implements the four standards that consolidated around AI-crawler monetization in 2025–2026 — [RSL 1.0](/docs/standards/rsl-1-0), [Web Bot Auth](/docs/standards/web-bot-auth), [HTTP 402](/docs/standards/http-402), and [x402](/docs/standards/x402) — in a vendor-neutral library you can audit, fork, and run on any framework.

## What it does

On every incoming request, the middleware:

1. **Recognises** declared AI crawlers via a curated catalogue of 30 user-agents (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, Applebot-Extended, Meta-ExternalAgent, Bytespider, CCBot, Cohere, Mistral, etc.).
2. **Verifies** cryptographic identity if the request carries Web Bot Auth signatures (Ed25519 + RFC 9421 HTTP Message Signatures per IETF `draft-meunier-web-bot-auth-architecture-05`).
3. **Applies** your RSL 1.0 robots.txt policy.
4. **Issues** HTTP 402 with Cloudflare-shape `Crawler-Price` / `Crawler-Price-Rail` / `Link` headers + a structured JSON payment offer when policy says so. Or 403 (block). Or 200 (allow) — with the decision forwarded to your route handlers via headers.

## What it doesn't do

- **Hold your money.** The Node middleware emits the 402 with a payment offer; the WordPress plugin goes further and seals content that unlocks against a payment made directly to you — by card on your own Stripe account or in USDC to your own wallet. See [settlement rails](/docs/concepts/settlement-rails) and the [unlock service](/docs/unlock-service).
- **Replace a CDN.** It runs at the application layer. Cloudflare / Akamai / Fastly handle edge-level concerns; CrawlerToll handles fine-grained policy where edge rules don't reach.
- **Identify scrapers that hide.** User-agent recognition only covers crawlers that declare themselves. On WordPress, sealing is the answer for premium content — an unidentified scraper gets the encrypted body; edge tools such as Cloudflare Bot Management handle the rest of a site.

## Where to start

Pick your framework — wiring is one line in all of them:

- [Express](/docs/getting-started/express) (Node, Express 4 + 5)
- [Fastify](/docs/getting-started/fastify) (Node, Fastify 4 + 5)
- [Hono](/docs/getting-started/hono) (Cloudflare Workers, Bun, Deno, Vercel Edge, Node)
- [Next.js](/docs/getting-started/next) (App Router middleware, Edge runtime)
- [WordPress](/docs/getting-started/wordpress) (PHP plugin, sealed paywall, 30-crawler catalogue)

Or use the framework-agnostic [`@crawlertoll/core`](https://www.npmjs.com/package/@crawlertoll/core) `decide()` function directly.

## How it's organised

| Layer | What |
|---|---|
| Decision engine | `@crawlertoll/core` — declared-crawler recognition + Web Bot Auth + RSL 1.0 + HTTP 402 |
| Framework adapters | `@crawlertoll/express`, `@crawlertoll/fastify`, `@crawlertoll/hono`, `@crawlertoll/next` |
| Settlement rails | `@crawlertoll/x402`; on WordPress, x402 + the publisher's own Stripe account |
| Publisher tooling | `@crawlertoll/publisher` — CLI + SDK for context-license.json |
| Buyer tooling | `@crawlertoll/client` — discover, query, verify attestation |
| Validators | `@crawlertoll/parser` — context-license.json schema validator |

All Apache 2.0. All on npm. Code on GitHub at [`github.com/charthouse-ltd`](https://github.com/charthouse-ltd).
